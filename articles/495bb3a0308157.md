## MVCとは
- MVCってそもそも何のためにある？
MVC（Model-View-Controller）が存在する目的は、
アプリケーションの役割を「データ」「画面表示」「処理の制御」に分け、コードを整理し、
変更や保守をしやすくすることです。

### なぜ役割を分けるのか
今回は、私が個人開発している登山初心者向けWebアプリ
[「やまッチ」](https://yamatchapp.com)の登山プラン機能を例に考えてみます。
もしこれらの処理が1か所にまとまり、
```
・登山プランをDBから取得する
・入力内容が正しいか確認する
・どの画面を表示するか決める
・HTMLを作る
・登山プランをDBへ保存する
```
それぞれの役割が分かれていなかったら、画面デザインを変更しただけなのに、DB保存に関係するコードまで触る可能性があります。
MVCでは大まかに、
```
Model
  → データやビジネスルールを担当

View
  → ユーザーに見せる画面を担当

Controller
  → リクエストを受け取り、
     ModelやViewをつなぐ役割を担当
```
と分担します。
だから、たとえば「登山プラン詳細画面の見た目だけ変更したい」なら、基本的にはViewを中心に変更すればよい、という考え方ができます。


## Model・View・Controllerの役割

### Model（モデル）

- データベースとのやり取り（データの取得・保存など）
- データに関するルールやビジネスロジック（入力チェック、関連付けなど）

### View（ビュー）

- Controllerから利用できるデータを元に、ユーザーが見るUI（画面）を組み立てる
- 基本的にデータ処理などの複雑なロジックは持たせない

### Controller（コントローラ）

- ブラウザからのリクエストを受け取る
- 必要に応じてModelを利用して、データの取得や保存を行う
- 処理結果に応じてViewによる表示につなげ、レスポンスを返す

※Controllerに多くの処理を詰め込むと、役割が分かりにくくなることがあります。そのため、「この処理はControllerが持つべきか、Modelが持つべきか」と責務を意識することが大切です。

## まとめ
これまではModel・View・Controllerがそれぞれ何を担当するのか、という程度の理解でMVCを使っていました。

今回改めて学習したことで、MVCは単に役割を3つに分けているのではなく、それぞれの責務を明確にし、変更や保守をしやすくするための考え方だと理解できました。

Modelはデータとそのデータに関するルールや処理、Viewはユーザーに見せる画面や表示、Controllerはリクエストを受け取り、必要に応じてModelを利用してViewによる表示につなげる役割があります。

今後はコードを書く際にも、「この処理はどの役割が持つべきなのか」を意識して実装していきたいと思います。
